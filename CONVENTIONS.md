# Соглашения репозитория

Документ фиксирует, как заводится и оформляется каждая новая лабораторная работа,
чтобы структура не расползалась от работы к работе.

## 1. Как завести новую работу

```bash
cp -r _template LR02
cd LR02
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
# установить зависимости работы
.venv/bin/python -m pip freeze > reports/environment.txt
```

`environment.txt` создаётся **после** установки зависимостей и **до** запуска
модели — он фиксирует ту среду, в которой получен результат.

## 2. Обязательные каталоги

| Каталог | Содержимое | Правило |
| --- | --- | --- |
| `assignment/` | методические указания, бланк варианта | коммитится как есть |
| `data/` | описание входных данных: prompt, его происхождение, проверка безопасности | текст, не бинарники |
| `src/` | исходный код | запускается из корня работы |
| `configs/` | параметры запуска одним JSON | единственный источник правды по параметрам |
| `artifacts/` | результаты запусков, по каталогу на запуск | каждый результат + `manifest.json` |
| `reports/` | `environment.txt`, журналы запусков, сравнения контрольных сумм | включая журналы неудачных запусков |

## 3. Что коммитится и что нет

Коммитится: код, конфиги, отчёты, журналы, манифесты, итоговые артефакты
разумного размера (PNG на несколько сотен килобайт — нормально).

Не коммитится (см. `.gitignore`): `.venv/`, `cache/` с весами моделей,
`__pycache__/`, `.DS_Store`, любые токены и ключи. Веса моделей восстанавливаются
по `model_id` + `revision` из конфига.

Если артефакт весит десятки мегабайт и больше — в репозиторий кладётся только
манифест и контрольная сумма, а сам файл выкладывается отдельно со ссылкой в отчёте.

## 4. Именование

- Работы: `LR01`, `LR02`, … — двузначный номер.
- Запуски: `artifacts/run_001`, `run_002`, … — трёхзначный номер, по каталогу на запуск.
- Журналы: `reports/run_001.log` — имя журнала совпадает с именем запуска.
- Приложения: `appendix_<буква>_<короткое_имя>/`.
- Файлы и каталоги — латиницей, строчными, через подчёркивание.

## 5. Манифест запуска

В `artifacts/<run>/manifest.json` обязательны поля: `model_id`, `revision`,
`prompt` (или иные входные данные), `seed`, параметры инференса, `device`, `dtype`,
`platform`, `python`, `packages`, измеренное время, путь к артефакту и `sha256`.

Правило: **по манифесту посторонний человек должен суметь повторить запуск,
не заглядывая в код.**

## 6. Контроль целостности

В корне работы лежит `MANIFEST.sha256` со всеми сдаваемыми файлами. Проверка:

```bash
shasum -a 256 -c MANIFEST.sha256      # macOS
sha256sum -c MANIFEST.sha256          # Linux
```

## 7. Структура отчёта

`REPORT.md` следует структуре, заданной методическими указаниями работы. Общий
скелет, если указания не задают иного:

1. Титульная информация и номер варианта
2. Цель, постановка задачи, критерии успешности
3. Происхождение входных данных, ограничения и лицензии
4. Среда, версии, модель и ревизия, устройство, параметры
5. Ход работы, команды запуска, существенный код
6. Результаты и их проверка
7. Ошибки, ограничения, угрозы валидности
8. Вывод по цели
9. Ссылка на репозиторий и индивидуальный вклад

## 8. Стиль выводов

Наблюдаемое значение записывается как наблюдаемое, ожидаемое — как ожидаемое.
Формулировка «SHA-256 совпал» допустима только со ссылкой на файл сравнения.
Границы вывода указываются явно: что именно доказано и что не доказано.
